## 1. 產品定位

「犬子老師・飆股雷達」是一個以台股為主、手機優先、零月費架構的決策雷達。核心不是預測必漲，而是把：

1. 大盤環境
2. 族群資金
3. 個股波段結構
4. 盤中動能
5. 籌碼背景
6. 進場位置
7. 當沖執行條件

拆開後再組合，讓使用者知道「股票本身好不好」與「現在能不能下手」不是同一件事。

固定聲明：**分數看條件是否同步，不代表上漲機率；大盤環境分獨立。**

## 2. 全站固定原則

### 2.1 市場顏色
- 台股習慣：**紅漲、綠跌**。
- 黃色：待確認／中性。
- 綠燈、黃燈、紅燈是「決策狀態」，不得與股價漲跌顏色混為同一意義。

### 2.2 視覺基調
- 主題預設：淺色。
- 背景：米白／淡灰白，不使用刺眼純白大面積。
- 卡片：白色或極淡灰綠。
- 主要文字：深灰黑／深墨綠。
- 次要文字：灰綠。
- 主操作色：墨綠。
- 深色模式保留切換，但不是預設。
- 手機優先；主要觸控高度至少 44px。

### 2.3 資料真實性優先
- 不把昨天資料冒充今天即時資料。
- 不把盤後籌碼冒充盤中即時籌碼。
- 當即時資料品質不合格時，必須降級為「最近完整資料／收盤定格」，並明確標示。
- 當沖不可執行時，不可顯示成「現在可執行」。

## 5. 四個主分頁

## 5.1 盤中｜找波段

### 任務
盤中找「正在轉強、適合波段追蹤」的股票，不等同於當沖。

### 個股資料來源
- 即時品質通過：使用 `intraday.json`。
- 即時品質不通過／休市：個股卡改用最近完整 `close.json` 波段資料。
- 但「資金動能」仍保留當日最後一筆盤中 `sector_rotation` 快照供復盤，不改成盤後法人流向。

### 畫面重點
1. 市場環境
2. 資金動能
3. 個股雷達搜尋
4. 今日波段機會／生命週期統計
5. 階段＋位置篩選
6. 個股卡
7. 更多市場資訊

---

## 5.2 盤後｜盤後作戰

### 任務
用完整日K、60分K、籌碼、族群與進場位置，整理隔日波段觀察名單。

### 個股資料來源
- `close.json`
- `market.json`
- `hourly.json`
- 籌碼資料

### 資金模組
- 名稱：**資金流向**
- 內容：盤後法人族群流入／流出。
- 法人流量以官方外資＋投信淨買賣股數搭配各日收盤價估算金額，用於力度比較，不額外灌入個股總分。

---

## 5.3 庫存｜我的庫存

### 任務
先看持股結構與風險，再決定續抱、減碼、加碼或出場。

### 固定規則
- 所有實際持有部位都要納入，包括 1 股零股／觀察倉。
- 僅計實際成交，不把掛單或取消單算進持股。
- 必須保留：進場理由、持有理由、理由狀態、驗證條件、結構失效條件、策略。
- 理由狀態：`✅ 成立 / ⚠️ 弱化 / ❌ 失效`。
- 核心進場理由失效優先處理；加分條件消失但核心結構仍在，不必機械式全出。
- 停損以結構確認為主，綜合 5/10/20MA、前低、量能、反抽失敗與大盤同步性。

### 資金模組
- 名稱：**資金背景**。
- 盤中即時合格時：可看盤中族群背景。
- 非即時／休市：使用最近完整盤後法人族群背景。

---

## 5.4 當沖｜當沖執行

### 任務
只處理「今天能不能執行」；與波段評分完全隔離。

### 規則
- `daytrade.json` 為獨立衍生資料。
- 不覆蓋 Stage 2.0、不覆蓋盤中波段分、不覆蓋盤後波段分。
- 波段資料與籌碼只能當背景，不加入當沖執行分。
- 即時品質不通過時：候選清單停用。
- 收盤後：保留最後資金動能快照供復盤，但明確標示「不可執行」。

## 6. 市場環境卡

固定內容：
- 市場狀態：偏多／中性／防守等。
- 市場分數：`x.x / 15`。
- 加權指數：指數值、點數漲跌、百分比。
- 櫃買指數：指數值、點數漲跌、百分比。
- 一句白話解讀。
- 交易日與更新時間。
- 台股顏色：紅漲綠跌。
- `查看市場細節` 預設收合，單擊即開、再單擊即關。

非即時狀態時，市場卡可使用最近完整盤後市場資料，但必須顯示正確交易日。

## 7. 資金模組規格

## 7.1 盤中／當沖：資金動能

資料來源：`intraday.json -> sector_rotation`。

第一層只顯示：
- 吸金 TOP 3
- 降溫 TOP 3
- 族群名稱
- 族群漲跌／成交占比等摘要
- 熱度／動能值
- `查看 N 檔`

**第一層不得一開始就鋪滿個股。**

第二層：點族群後才展開該族群個股。

第三層：點個股名稱後才開「個股小卡」。

### 收盤定格
- 盤中結束後不切成盤後法人流向。
- 保留當日最後一筆資金動能快照。
- 顯示：`M/D HH:MM 收盤定格資金動能`。
- 當沖頁另加「不可執行」語意。

---

## 7.2 盤後：資金流向

資料來源：`close.json -> sector_funds`。

顯示：
- 主要流入 TOP
- 主要流出 TOP
- 族群金額／張數等摘要
- 點族群後顯示族群個股
- 點個股後開小卡

---

## 7.3 個股小卡

視覺：淺色系，與主站一致。

目前要保留的欄位：
- 股票名稱＋代碼
- 所屬族群
- 當日漲跌
- 生命週期 badge
- 現價
- 盤中動能／對應分數
- 同時間量速
- 距 VWAP
- 族群共振
- 籌碼背景
- 生命週期解讀
- 主要正向訊號／風險訊號
- `查看完整個股`
- `加入庫存`
- `關閉`

### 最重要的資料一致性規則
若從資金動能清單點進某檔：

**清單 → 小卡 → 查看完整個股**

三層必須沿用**同一筆來源 row、同一分數、同一生命週期、同一交易日**。
不得在中途切回另一份 `closeRows / intraRows / daytradeRows` 導致「79 剛啟動 → 61 觀察」這類矛盾。

## 8. 個股雷達／搜尋／篩選

### 8.1 搜尋
- 可輸入股票代號或名稱。
- 搜尋後仍以目前分頁的 canonical source 為準。
- 不允許同一股票因入口不同而取不同資料版本。

### 8.2 預設顯示
- 初始清單保留 15 檔。
- `查看更多` 每次 +15 檔。
- 所有展開／收合與查看更多都要求單擊即反應。

### 8.3 生命週期快速篩選
- 🌱 蓄勢
- 🔥 剛啟動
- 🟡 回踩
- 🚂 趨勢
- ⚠️ 轉弱／失效
- 🚫 過熱

- 🟢 位置可觀察

- ✨ 精選機會

## 9. 評分系統

## 9.1 盤後波段品質分 100

基準 component：
- 技術：50
- 籌碼：25
- 族群：15
- 流動性：10
- 合計：100

另有：
- **進場位置分 100**：獨立，不混入股票品質。
- **大盤環境分 15**：獨立，不混入股票品質。

盤後品質標籤：
- ≥80：高延續
- ≥70：強
- 其他：一般
- 籌碼覆蓋不足時：資料待補

歷史 validation 可調整各 component 在 100 分中的相對權重，但原始 component 尺度仍維持 50/25/15/10。

---

## 9.2 盤中波段執行分 100

盤中籌碼只作背景，不計入即時動能分。

- 價格結構：30
- 量價／動能：25
- 相對強弱：15
- 族群：20
- 流動性／追價風險：10

品質標籤：
- ≥82：強動能
- ≥70：轉強
- ≥55：中性
- <55：轉弱

---

## 9.3 當沖獨立分 100

- 執行價格結構：30
- 量價／即時推進：25
- 相對強弱＋族群確認：20
- 進場時機／波動效率：15
- 流動性／追價風險：10

狀態機：
- 可執行
- 等回踩
- 觀察
- 過熱不追
- 失效

可執行的核心要求包含：高分、執行結構、量價、相對族群、流動性、站上 VWAP、5分趨勢、非防守盤等同步成立。

## 10. Stage Engine 2.0｜生命週期

Stage 只描述生命週期，**不等於總分**。

固定狀態：
1. 蓄勢待發
2. 剛啟動
3. 回踩承接
4. 趨勢持有
5. 觀察
6. 轉弱警戒
7. 結構失效
8. 過熱不追

### 10.1 盤中 Stage
主要看：
- VWAP
- 5分結構
- 3K／12K 突破
- 量速
- 15分鐘報酬
- 相對市場
- 族群共振
- 60K 20T/60T 狀態
- 日K背景
- 多時間框相對強弱

典型邏輯：
- 剛啟動：3K突破＋站上VWAP＋量速≥約1.1x＋相對市場不弱，且 60K／多時框沒有明顯反向。
- 回踩承接：原結構夠強，價格回到 VWAP 附近，15分鐘未急殺、相對市場未明顯轉弱。
- 趨勢持有：動能≥約70、站上VWAP、相對市場≥0、5分／12K結構仍在。
- 蓄勢待發：尚未突破，但價格、量能、相對強弱、族群與多時框至少多項集中。
- 轉弱／失效：需要價格、VWAP、15分鐘、相對強弱、量能與短線趨勢多證據同步，不因一根雜訊K就失效。

### 10.2 盤後 Stage
主要看：
- 5/10/20MA
- 20日／3日平台突破
- MACD
- RSI
- 量比
- 距20MA
- 近5日漲幅
- 波段品質分
- 籌碼
- 族群共振

典型邏輯：
- 剛啟動：突破成立＋量比≥約1.2＋位置未過度延伸＋技術／波段品質足夠。
- 回踩承接：守在20MA附近、短線未延伸、量能未失控、原趨勢仍在。
- 趨勢持有：均線結構支持、波段品質足夠、距20MA仍在合理範圍。
- 蓄勢待發：尚未正式突破，但均線、MACD、RSI、量能、位置、籌碼、族群條件集中。
- 結構失效：採嚴格多證據確認，例如明顯跌破20MA＋中期均線失守＋動能深度轉弱。
- 轉弱警戒：比一般回檔嚴格，需要核心價格／均線弱化＋多項同步負面證據。

## 11. 雙軸決策

波段卡片固定拆成：

### 軸 1：股票／波段結構
回答：**這檔股票值不值得抱／追蹤？**

### 軸 2：現在位置
回答：**現在是不是漂亮的下手位置？**

最後輸出：
- 🟢 可試單
- 🟡 等回踩／等確認
- 🔴 不追

原則：好股票不等於現在可以追。

當沖則改成：
- 軸 1：盤中執行品質
- 軸 2：現在位置

兩者都過關才可執行。

## 12. 60 分 K／多時間框

需保留：
- 60K 20T / 60T 黃金交叉
- 尚未交叉但 PRE_CROSS
- 已黃金交叉一段時間，只要斜率與趨勢仍健康仍可列入
- 60K supportive / bearish
- 日K bullish / weak
- 5分＋60分＋日K的多框共振判讀
- 多時間框相對強弱（LEADING / IMPROVING / LAGGING 等）

已交叉不因「不是剛交叉」就自動排除。

---

## 13. 籌碼與族群

### 籌碼背景
至少保留：
- 外資
- 投信
- 融資
- 借券賣出
- 籌碼覆蓋率
- 集中度（有資料時）

既有偏好篩選：
- 外資連續 3 日買超
- 借券賣出連續 3 日減少
- 同族群至少 3 檔共振優先
- 排除短線過度延伸
- 排除成交量過低
- 保留基本面／題材支撐

### 族群分
優先用次產業／題材群組；沒有窄群組時用官方產業代理。
族群共振需綜合：
- 上漲廣度
- 強勢股比例／成交金額占比
- 活躍度
- 領漲股數
- 趨勢延續比例

## 14. 資料檔與更新流程

核心資料檔：
- `close.json`：盤後完整波段資料
- `intraday.json`：盤中資料／sector_rotation
- `daytrade.json`：獨立當沖資料
- `market.json`：市場環境
- `universe.json`：上市上櫃股票清單
- `hourly.json`：60K／多時間框
- `validation.json`：歷史驗證／校準
- `status.json`：更新資訊
- `system_status.json`：canonical 資料狀態

### 盤中排程
- 交易日台灣時間約 09:00–13:59。
- GitHub Actions 約每 5 分鐘更新一次。
- 更新：intraday → daytrade → hourly → validation → system status → publish。

### 盤後排程
台灣時間：
- 14:25：第一版盤後
- 20:30：補晚公布籌碼
- 23:40：再補一次
- 次日 08:15：最終補齊

盤後發布前必須驗證：
- 籌碼不是全數 0 coverage
- hourly 不可為空
- canonical system status 有最新完整交易日

## 15. 即時品質與安全門檻

系統目前安全視窗：台北時間工作日約 `08:55–13:35`。

盤中即時 Ready 需同時滿足：
- intraday 日期＝今天
- 非 stale
- MIS 覆蓋率達最低門檻（預設約 80%）
- 有可驗證最新報價時間
- 有可驗證 5分結構時間
- 報價年齡 ≤12 分鐘
- 5分結構年齡 ≤20 分鐘

當沖 Actionable 另外要求：
- daytrade 日期＝今天
- 非 stale
- intraday liveReady=true

不通過時：
- 盤中個股雷達 → 最近完整盤後波段資料
- 盤中資金動能 → 保留最後盤中快照供復盤
- 當沖候選 → 停用
- 當沖資金動能 → 可顯示最後快照，但不可標成可執行

---

## 16. 互動規格

所有互動必須「一次點擊即完成」：
- 查看市場細節
- 查看完整資金動能／流向／背景
- 查看 N 檔族群個股
- 展開個股分析
- 查看更多
- 主導覽切換

### 展開狀態
- 背景資料更新時，不得把使用者剛打開的區塊瞬間關掉。
- 不得讓多個 click handler 同時控制同一個 details。
- 不得用每秒整頁重畫維持 UI。

### 資料更新
- 只有資料真的變化才更新對應區塊。
- 不得為了資料更新重建整頁 DOM。

---

## 17. 啟動流程規格

使用者開站時：

1. 只看到一套正式 loading 畫面。
2. UI 骨架與必要資料準備完成後，一次進入正式畫面。
3. 不得先露出舊版 HTML，再變新版。
4. 不得中途被 Service Worker 強制 reload。
5. 不得「正確樣式已出來，但所有數據仍是 0 / —」。
6. 大資料下載失敗可重試／使用最後成功快取，但必須標示資料日期。

## 18. 現行前端技術負債｜Clean Build 不得照搬

現行 loader 為 `ui-filters.js`，仍會依序載入多代 CSS 與約二十個 JS 模組，包括 `redesign-v160`、`v162`、`v163`、`v164`、`v166`、`v1685`、`v1690`、`v1701`、`v1702`、`v1720`、`v1730`、`v1751` 等。

目前已知問題來源：
- 多代 CSS 同時控制同一元素。
- 多支 JS 同時 wrap / render 同一份 card。
- 多個 MutationObserver 監看相同 DOM。
- 舊版與新版都有 render ownership。
- 安全守門會暫時替換 rows，再呼叫舊 render。
- 資料 bootstrap、UI module、market module 都可能觸發重畫。
- 歷史上曾存在「每秒整頁 repaint」的自癒迴圈。
- `<details>` 曾被背景 render 重建造成按一次又被關回去。
- Service Worker／cache bust 歷史版本多，手機容易短時間混用舊資源。

**Clean Build 原則：以上架構一律不繼承。**

---

## 19. Clean Build 必須採用的新技術邊界

### 19.1 單一 ownership
- 1 個 app entry
- 1 個 global state
- 1 個 data service
- 1 個 router/view state
- 每個畫面區塊只有 1 個 renderer/component owner
- 每種互動只有 1 個 event handler owner

### 19.2 禁止
- 禁止 patch A 再 patch B 修 patch A。
- 禁止 MutationObserver 當主要狀態管理。
- 禁止改全域 `rows` 來暫時欺騙另一支 renderer。
- 禁止整頁 innerHTML repaint 當資料更新方式。
- 禁止 UI 版本與資料版本彼此靠 timing 猜測。

### 19.3 canonical state
Clean Build 需要明確狀態：
- `view`: intraday / close / portfolio / daytrade
- `dataMode`: live / frozen / close / disabled
- `tradeDate`
- `quoteTime`
- `structureTime`
- `selectedSector`
- `selectedStock`
- `expandedSections`
- `filters`
- `theme`

所有畫面都只從 canonical state render。

## 22. 本規格的定位

這份文件是 **「要保留的產品」**，不是 **「要保留的舊程式」**。

重建時可以完全改寫 HTML / CSS / JS 架構，但：
- 分頁目的
- 使用流程
- 資料真實性
- 分數定義
- Stage 邏輯
- 資金動能／流向差異
- 庫存規則
- 當沖隔離
- UI 風格
- 使用者已確認的互動方式

都必須以本規格為基準逐項驗收。
